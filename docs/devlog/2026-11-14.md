## Decisions / learnings
- **Rule A (PO):** an invalid barcode quarantines only the identifier; the alert stays in silver. Same idea for photos and unknown risk levels: a data problem must never hide a dangerous product.
- **Full rebuild for silver** while bronze is small (~97k rows, ~1.5 min); `MERGE` only from ~10M rows. Simple and always correct: silver = rules(bronze).
- **`sg_alert_texts` dropped:** the EC sends one complete record per language, so `sg_alerts` is keyed by `(case_number, lang)`.
- **Never guess the order of files:** the bulk upload on Day 6 gave both files of a corrected report the same time, and one pair (Report-2026-40 EN) was ordered wrong, so an old text showed as current. Fixed by re-uploading in the right order; silver now **stops** when the order is ambiguous. The real fetch time will be recorded per file (#42).
- **The EC changes old reports:** today it served new files for Reports 2026-21 to 2026-26. Of 505 re-delivered alerts per language, only 10 really changed and became new versions; the rest collapsed. So downloads must run every week (#43).
- **Measure before planning:** photos are 197 KB on average (not 150 KB) but only 2.4 per alert (not 3.3). The whole history is ~20 GB and 5.8 h at 5/s, not 50 GB / 18 h.
- **Security gate worked:** `pip-audit` in CI blocked Pillow 12.0.0 (known holes). Pillow decodes files from the internet, so the notebook now installs the patched 13.0.0 and stops on any other version.
- **Databricks Git folder:** running a notebook can change its file. Before every Pull or branch switch: "No changed files", otherwise discard. Never edit there; laptop → commit → push → Pull.
- **Serverless details:** Python 3.12; Python UDFs import our package when it is shipped by value (`cloudpickle.register_pickle_by_value`); the internet is reachable, so photos go straight into the volume.
