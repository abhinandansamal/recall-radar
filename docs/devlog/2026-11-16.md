## Decisions / learnings
- **Three AI workloads, three levels:** screening is a fixed pipeline in plain code (high volume, must be fast, cheap and predictable); the assistant is routed RAG; only the case workflow is an agent (LangGraph, human approval). No agent where a pipeline is enough.
- **Exact keys before any AI:** a barcode or brand + model match is decided in code, so the 100 % rule never depends on a model.
- **Cascade:** most listings are clear after retrieval and never reach the LLM; this keeps screening cheap (estimated ~$2–3 per month for the judge).
- **Models by bake-off on our own gold set,** not by public benchmarks; the embedding model gets the most care because it is the hardest to change.
- **PO rule: evaluation at every stage.** A later stage cannot fix an earlier one (no reranker helps if retrieval misses the alert). Each stage has a metric, slice and threshold; wrong results are labelled with the first failing stage.
- **PO rule: security by design.** The main attacker is a dishonest seller who writes listing text. Controls live in code, data and roles, not in prompts; attack tests are gates with a threshold of zero.
- **Cost check:** the expensive role is the case agent; if a small model passes its tests, the LLM total drops from ~$19 to ~$5 per month.
