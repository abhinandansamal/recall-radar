## Decisions / learnings
- **Read the source before writing the code.** Each check today found something:
  - URLs inside XML contain `&amp;`, so always use an XML parser, never `grep`.
  - A wrong URL returns an HTML error page with **HTTP 200**, so every download is validated by content.
  - The EC serves the same report in two XML styles (empty CDATA vs `xsi:nil`). The fingerprint is computed over the meaning (tags + text), not the bytes. Proof: a re-download wrote 0 files.
  - Real corrections exist: Report-2026-22 and Report-2026-40 changed during the day. They are stored as new versions; silver resolves the history (SCD2).
  - EUR-Lex blocks scripts (HTTP 202, empty body, `x-amzn-waf-action: challenge`). Cellar (`publications.europa.eu/resource/celex/…` with `Accept` and `Accept-Language`) is the official route for programs.
- **Logging bug:** structlog's `.bind()` builds the logger immediately with the default config. Initial values via `structlog.get_logger(**values)` keep it lazy. The field is now `logger_name` (`logger` is reserved by structlog).
- **Branch protection:** "require up to date" blocks merges when the PR head is stale. After a GitHub 500 on push, the branch had the commit but the PR did not; an empty commit re-synced it.
- **Sizes:** about 47.6k alerts per language since 2005 (estimate was up to 100k); photo download needs measuring before planning (about 3 s per file today).
- **Tooling:** Homebrew now requires trusting third-party taps (`brew trust --formula …`); `databricks` CLI with `auth_type = azure-cli` needs no token; `sips -Z 1400` keeps screenshots under the 500 KB hook.
- Scope over date: all v1.0 features stay; the release date may move instead (PO decision at the Sprint 1 review).
