# F03: ABO catalogue profile and overlap with Safety Gate (US-008)

- Date: 2026-11-15
- Issue: #23 (US-008)
- Notebooks: `pipelines/bronze/abo_bronze.py` (landing + bronze), `pipelines/profiling/abo_profile.py`
- Mapping (Product Owner decision): `pipelines/reference/abo_category_map.csv`
- Data: Amazon Berkeley Objects, listings + image metadata (17 files, 94 MB), catalog `rr_dev`

## Question

Is Amazon Berkeley Objects (ABO) a realistic catalogue for RadarMart, and in which Safety Gate
categories can matching be tested on it?

## Method

1. Copy the 16 listing files and `images.csv.gz` unchanged from the public S3 bucket into the landing
   volume (size and gzip checked, write-once; a second run downloads nothing).
2. Profile all 147,702 listings: product types, filled fields, languages, markets, images.
3. Propose a Safety Gate category per ABO product type with whole-word keyword rules
   (`rr_ingest.abo.propose_category`), then **review by hand** (PO decision): wrong proposals removed,
   missed types added, every one of the 576 types listed with `include = true/false`.
4. Measure the overlap: ABO listings and Safety Gate alerts (current, English) per category.

## Decisions

- **Subset = all 39,324 listings of the 197 types (PO, 2026-11-15)**, footwear included (16,819
  listings): a realistic, shoe-heavy marketplace mix, and Safety Gate has footwear alerts (e.g.
  chromium VI in leather). Bronze stays small; steps that cost money later (photo download,
  embeddings) can cap per category.
- **Bronze:** `bronze.abo_listings_raw` (39,324 rows, all fields unchanged plus `product_type_value`,
  `sg_category`, `_source_file`, `_ingested_at`, `_licence`) and `bronze.abo_images_raw` (122,645 image
  records of these listings). Checks: every main image has metadata, every row has the licence.
- **Licence:** CC BY 4.0 per bucket README and `LICENSE-CC-BY-4.0.txt` (relicensed 2023); the AWS
  registry and the 2022 paper still say CC BY-NC 4.0. Recall Radar is non-commercial and attributes the
  source, so it satisfies both. The text is stored on every bronze row.

## What this means for matching (input for F06 evaluation)

1. **No barcodes in ABO.** Exact GTIN matching cannot be tested on ABO; it is tested on Safety Gate
   alerts that have barcodes (28 % of alerts, US-010 profile). On ABO the exact path is
   brand + model number (model number filled for 84 %).
2. **Toys are the biggest gap** (23 % of all alerts, 84 ABO listings). As planned in
   `docs/data/data-sources.md`, toys are evaluated on Safety Gate data only (image to alert,
   German to English).
3. **Motor vehicles and machinery have no ABO listings** (15.3 % of alerts together); they are out of
   scope for a consumer marketplace demo.
4. **ABO is mostly Amazon's own goods**, so true matches with Safety Gate alerts will be rare. ABO is the
   realistic catalogue and the source of **hard negatives** (similar but safe products) to measure
   false positives, especially in jewellery, lighting, electrical, cosmetics and clothing.
5. **German coverage is limited** (10.2 % of titles): German-language matching is tested mainly with
   the German texts of Safety Gate alerts.
6. **1,505 duplicate `item_id`s** in the subset (same item in several markets). Bronze keeps them as
   delivered; the ABO silver step must decide which row represents an item in RadarMart.
